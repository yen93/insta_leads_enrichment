Insta Leads Enrichment — User Guide

Insta Leads Enrichment automatically finds the right people to contact at each organisation captured from our Instagram-story leads. It looks each company up on Hunter.io and fills in contact names, job titles, and email addresses in our leads database — so the sales team starts with real points of contact instead of just a company name.

What This Is

Every time we capture a lead from an Instagram story, we record the organisation behind it — but not who to actually email. This tool closes that gap. For each organisation that still needs contacts, it searches Hunter.io for people at that company and writes them back into the leads table, one entry per person found (their name, position, and work email).

It runs as an automated Claude Code routine called insta_leads_enrichment. There is also a script version that does exactly the same thing if you prefer to run it from a computer.

Who This Guide Is For

  • Sales and lead-generation team — anyone who works from the enriched leads and wants to understand where the contact names and emails come from.
  • The routine owner / operator — whoever triggers or schedules the routine and reviews its results.

You do not need to be technical to use it. If you can open a web page and click a button, you can run it.

How to Use It

The routine now runs automatically once a day at 8:30 AM Philippine time — the daily run needs no action from you. You can also start it yourself whenever you need it sooner:

  1. Let the daily schedule run it (nothing to do). Every day at 8:30 AM Philippine time the routine starts on its own and works through any leads that still need contacts.
  2. Run it on demand. To enrich leads without waiting for the next daily run, open the routine at claude.ai/code/routines/trig_01EZuVzMvdW5Gyq5VVyvKjgk and run it once. It can also be started from another system via an API trigger.

What to Expect

  • It runs automatically every day. The routine fires once a day at 8:30 AM Philippine time, so you don't need to trigger it for the daily run.
  • It only touches leads that still need contacts. Each run looks for leads that have an organisation but haven't been enriched yet, and skips everything already done — so it's safe to run again and again without creating duplicates of already-processed leads.
  • One entry per selected contact. If Hunter returns several people for a company, the tool adds a separate lead row for each person whose job title is one of the preferred roles (see below), carrying over the original story's details and filling in that person's name, position, and email.
  • It prefers the roles we care about — but always finds someone. Contacts are preferred when their Hunter job title matches one of these roles: Conference / Events Manager, Marketing Manager, Communication Manager, Learning & Development Manager, People & Culture Manager, Executive Assistant, or Human Resources / HR (including recruitment, talent acquisition, and people operations). Matching is flexible, so close variants (for example "Head of Marketing", "Events Coordinator", or "HR Business Partner") count too. If a company has nobody in those roles, the tool keeps one other contact person from that company instead (preferring a named person over a generic inbox like info@), so every company we can find online ends up with at least one point of contact.
  • Every lead gets marked as processed. Once a lead has been looked up it is flagged as done — even if no contacts were found — so it won't be looked up again.
  • Turnaround. A run in the cloud typically finishes in a couple of minutes, depending on how many organisations need looking up.
  • A short summary at the end. Each run reports how many leads it processed and, for each organisation, which company domain it matched and how many contacts it added.

Known Limitations

Being upfront about what it does not do saves a lot of "why didn't it…" questions:

  • Up to 10 contacts per organisation. Our Hunter.io plan returns at most 10 people per company, so very large organisations will only show the first 10.
  • Company matching can occasionally be wrong. Hunter guesses a company's website from its name. For small or ambiguously named organisations it can match the wrong company (for example, "HerTri London" once matched an unrelated insurance broker). The run's summary flags any organisation whose matched domain looks off — it's worth a quick review after each run.
  • Emails are not verified or contacted. The tool records the contacts Hunter provides; it does not send any emails, and it doesn't independently verify that every address is deliverable.
  • The same organisation can appear more than once. If two separate Instagram stories mention the same company, each is enriched on its own, so you may see the same set of contacts added twice.
  • No notifications. It doesn't email or message you when it finishes — you read the outcome in the run summary.
  • It does not add leads to the Google Sheet. Enrichment only fills contacts in the database. Getting those rows into the working spreadsheet is handled by a separate process.

How It Was Built (Architecture & Tech Stack)

End to end, a single run works like this:

  • Find the work. It queries our leads database for rows that have an organisation but haven't been enriched yet.
  • Look up each organisation. For every one, it calls Hunter.io's Domain Search to find people at that company — their name, job title, and email.
  • Write the selected contacts back. For each person found in one of the preferred roles, it adds a new lead row that carries over the original story's details and fills in that contact. If no one at the company is in those roles, it adds one other contact from that company instead, so the company still gets a lead.
  • Mark it done. It flags the original lead as processed so it won't be picked up again, then reports a summary.

Under the hood it uses:

  • Claude Code cloud routine — the automated agent (insta_leads_enrichment) that carries out the steps, running on the Claude claude-sonnet-5 model.
  • Supabase (the insta_stories table) — the leads database that is read from and written to.
  • Hunter.io Domain Search API — the source of contact names, positions, and emails.
  • A Python script alternative (enrich_leads.py) — runs the identical process from a computer for anyone who prefers that.

Troubleshooting

  • The run said "no rows to process." That's normal — it means every current lead with an organisation has already been enriched. New leads will be picked up on the next run.
  • A lead's contacts look like the wrong company. Hunter matched the wrong website for that organisation's name. Check the domain noted in the run summary; those contacts can be ignored or removed.
  • An organisation only shows a few contacts. Hunter only returned that many, and results are capped at 10 per company — this is expected, not an error.
  • The same contacts appear twice for one company. That company came from more than one Instagram story, and each is enriched separately.
  • Nothing seems to be happening. The routine runs once a day at 8:30 AM Philippine time, so new leads are picked up at the next daily run. If you need them sooner, open the routines page and run it on demand.
